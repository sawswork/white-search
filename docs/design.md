# White Search 設計書（2026-11-20 第3版）

## 1. コンセプト
リンク一覧を出さない検索エンジン。何もない白い画面に問いを書き、
出てきたトピックを選んで進むだけで、知りたい答え1つだけに届く。

- 遮断する：広告、関連記事、サムネイル、おすすめは一切出さない
- 選んで進む：キーワードを考え直さず、3〜5個のトピックから1つを選ぶ
- 絞る：選ぶたびに情報が減り、最後に答え1枚だけが残る
- 道のりが残る：どう調べて答えに着いたかが、線で結ばれた図として残る
- 外に出さない：標準では問いも履歴も端末の外に出ない

名称：White Search
リポジトリ：white-search
対象：iPhone（Apple Intelligence対応機種）。確認はiPadでも行う

## 2. 体験の流れ
1. 起動：完全に何もない白い画面。初回のみごく薄い文字で入力を促す
2. 入力：打った文字だけが画面に現れる（文字、または画像）
3. 送信：下にスワイプする。検索ボタンは置かない
4. 選ぶ：画面の下側にトピックが3〜5個出る。1つタップする
5. 絞る：選んだトピックは上に小さく残り、次の階層のトピックが下に出る
6. 答え：十分絞れたら答えカードが1枚出る（目標は2〜4タップ）
7. 履歴：たどった道のりを、線で結んだ木の図で見る

## 3. 機能要件

### 3.1 入力
- 起動直後は白い画面のみ。キーボードは開いた状態
- 点滅するカーソルは非表示
- 初回起動時のみ、画面中央に薄い墨色（不透明度25%程度）で「問いを書く」と表示し、
  1文字入力した瞬間に消す。以後は出さない
- 下スワイプで送信。キーボードの確定キーでも送信できる
- 初めての送信が完了するまで、文字入力後に画面下端へ
  「↓ 下に引いて送る」のヒントを淡く表示する。一度送ったら以後は出さない
- 画像（撮影、写真の選択、貼り付け）からも検索を始められる
- 画像入力への導線：常設ボタンは置かず、画面の長押しメニュー
  （ペースト／写真を撮る／写真から選ぶ）から呼び出す
- クリップボードに画像がある場合は、控えめに「画像を貼る」と表示する
- 添えた画像は入力欄の上に小さく表示し、タップで外せる
- 画像だけで送った場合、問いの文言は「この画像について」とする
- 画像は向きを正し、長辺1024pxまで縮めて保存する

### 3.2 トピック提示
- 1階層につき3〜5個。各15文字以内の短い言葉
- トピック同士は意味や粒度が重ならないようにする（切り口を揃える）
- 親指で押しやすいよう、画面の下側に並べる
- 問いと、これまで選んだトピックは画面の上側に小さく残す
- 合うものがなければ「別の候補」で出し直すか、言葉を足す
- 「別の候補」では、直前に出した候補を避けて生成する
- 「戻る」で1つ前の階層に戻れる

### 3.3 答え
- 十分絞れたとAIが判断したら答えを出す（canAnswer）
  ただし最初の階層（まだ何も選んでいない状態）では必ずトピックを出す
- 最大4階層で必ず答えに切り替える
- 途中でも「答えを見る」でその場の答えを出せる
- 答えカードは、結論1文と要点3〜5行
- 答えには作った場所を小さく示す（「端末内AIで生成」「Appleのクラウドで生成」）
- 「もっと詳しく」を押したときだけ、Appleのクラウドで詳しい答えを作り直す。
  一度詳しくした答えには、もう「もっと詳しく」を出さない
- 最新の出来事、価格、営業時間などは端末内では答えられない。
  その場合は「端末内では答えられません」と正直に出す
- 外部Web検索（オプトイン）：標準ではオフ。設定で有効にした場合のみ、
  答えカードの下部に「Webで確認する（外部へ送信）」を表示し、
  明示的な1タップで、端末に設定されている検索エンジンへブラウザ経由で橋渡しする。
  渡す言葉は、問いと選んだトピックをつなげたもの

### 3.4 履歴マップ
- 1回の検索を1本の木として保存する（問いが根、トピックが節、答えが終点）
- たどった道は濃い線、選ばなかった枝は薄い線で描く
- 薄い枝をタップすると、そこから調べ直せる。新しい道は同じ木に追加する
- 履歴一覧は日付順（新しいものが上）
- 画像つきの問いは、木の上に画像を小さく表示する
- 1件ずつ、または全件を削除できる。削除時は画像ファイルも消す

### 3.5 収益化
- 広告はコンセプトに反するため入れない
- 無料版 ＋ 買い切りアンロック

| 項目 | 無料版 | 有料版 |
| --- | --- | --- |
| 検索回数 | 1日5回まで | 無制限 |
| 履歴の保存 | 新しい20件まで | 無制限 |
| 画像からの検索 | 使えない | 使える |

- 回数は端末内で数える（アカウントがないため、入れ直すとリセットされる。許容する）
- 回数を消費するのは新しい問いを始めたときだけ。
  絞り込み、出し直し、履歴からの調べ直しは数えない
- 端末内AI中心で運用費がほぼかからないため、買い切りを基本とする
- 将来クラウドの費用が膨らむ場合は、「もっと詳しく」にだけ上限を設けて守る
- 上限に達したときと課金画面も、白い画面に文字だけで見せる
- 課金処理（StoreKit）は未実装。当面は設定画面の試験用スイッチで切り替える

### 3.6 設定
履歴の画面から開く。

- 「もっと詳しく」を使う（標準：オン）
- 「Webで確認する」を使う（標準：オフ）
- 履歴を開くときに本人確認をする（標準：オフ）
- すべての履歴を削除
- 有料版として動かす（試験用。課金実装後に削除）
- 状態の表示：使っているAI、画像検索の可否、「もっと詳しく」の可否

### 3.7 入れないもの
- アカウント、ログイン、端末間の同期、共有機能
- 分析ツール、広告、外部の計測部品、外部SDK
- 自前のサーバー

## 4. AI構成
端末内AIを基本にし、詳しい答えが欲しいときだけAppleのクラウドを使う2段構え。
どちらもAppleのFoundation Modelsフレームワークから呼び出す。

| 処理 | 動かす場所 | 理由 |
| --- | --- | --- |
| 問いをトピックに分ける | 端末内 | 短い定型出力で、小さなモデルでも質を出せる |
| 画像の内容を読み取る | 端末内 | iOS 27で画像と文字を一緒に渡せる |
| 答えカード（標準） | 端末内 | 通信なしで即座に出せる |
| 答えカード（もっと詳しく） | Private Cloud Compute | 大きなモデルで誤りを減らし詳しく書ける |
| 履歴の保存と表示 | 端末内 | AIを使わずデータの読み書きだけで完結 |

### 4.1 端末内AIの制約と対策
- 一度に扱える量は4,096トークンまで
  → 階層ごとに新しいセッションを作り、渡すのは問いと選んだトピックの列だけ
- 出力の形が崩れないよう、型を指定して生成させる（guided generation）
  トピック：文字列3〜5個 ＋「もう答えられるか（canAnswer）」の真偽値
  答え：結論1文 ＋ 要点3〜5個
- Apple Intelligence対応機種でしか動かない
  → 使えない端末では仮データ（MockEngine）で動き、落ちないようにする。
    正式版では起動時にその旨を伝える

### 4.2 AIへの指示文
共通の指示：
  あなたは検索を絞り込む案内役です。必ず日本語で答えます。
  余計な前置きや関連情報は出さず、聞かれたことだけに答えます。

トピック生成：
  問い、（画像があればその旨）、これまでに選んだ絞り込み、を渡し、
  「この問いに的確に答えるために、次に選ぶべき観点を出してください。
   観点同士は意味が重ならず、同じ細かさにそろえてください。」
  出し直しのときは「次の候補は出さないでください：…」を足す

答え生成：
  問い、（画像があればその旨）、絞り込み、を渡し、
  「この絞り込みに沿って、問いに答えてください。確かでないことは書かないでください。」
  「もっと詳しく」のときは
  「要点は理由や具体的な数値も含めて、詳しく書いてください。」を足す

### 4.3 Private Cloud Compute（PCC）の条件
- App Store Small Business Programに登録し、累計初回ダウンロード
  200万件未満なら、クラウドAPI費用なしで使える
- 専用の権限（com.apple.developer.private-cloud-compute）の申請が必要。
  承認が下りるまでは権限を入れない（入れると署名に失敗する）
- ユーザーごとに1日の利用上限がある
- 上限に達したときや通信できないときは、端末内の答えをそのまま残す
- 権限がない間は「もっと詳しく」を自動的に出さない

## 5. セキュリティとプライバシー
- 標準の状態では、アプリは一切通信しない
- 外に出るのは、ユーザーが「もっと詳しく」またはオプトインの
  「Webで確認する」を押したその1回だけ
- 外部通信を行う操作のそばには、問いが外に送られることを常に明記する
- 設定でクラウド利用・外部検索をオフにすると、該当ボタン自体が画面から消える
- 履歴と画像は端末内にファイル保護つきで保存し、バックアップの対象から外す
- 履歴を開くときに本人確認（Face IDなど）を求める設定を用意する
- アカウントがないので、誰が使っているかをアプリ側が知る手段がない

## 6. デザイン方針
見た目は後から設計する。現在の画面は機能確認用の仮のもの。
決まっている方針のみ記す。

- 極限までシンプルで、Appleのアプリのように洗練された印象
- 画面にあるのは白い地と文字だけ
- 色は白、墨色、アクセント1色（仮：藍色）
- 枠、影、アイコンの列、タブバー、ロゴは置かない
- 選択肢は罫線の表にせず、画面下部に間隔を空けて並べる
- 選択肢の文言は短く（例：「豆の焙煎度で変わる」より「豆の焙煎度」）
- 片手で最後まで操作できる
- トピックは生成された順に、上から1つずつ現れる
- 送信時と選択時に軽い触覚フィードバック
- スワイプから最初のトピックが見えるまで1秒以内が目標
- 文字サイズ拡大、VoiceOver、ダークモードに対応

## 7. データ構造
節（Node）
- id
- 種類：問い / トピック / 答え
- 文言
- 要点（答えのときだけ）
- 親の節
- 子の節の一覧
- たどった道かどうか
- 画像ファイル名（問いのときだけ）
- 答えを作った場所（答えのときだけ）
- 詳しく作り直したかどうか（答えのときだけ）

木（SearchTree）
- id、日付、根の節、全節の一覧

保存先：Application Support 内のアプリ専用フォルダ
- history.json：全履歴
- 画像：1枚ずつJPEGファイル
ファイル保護を有効にし、フォルダごとバックアップ対象外にする。

端末の設定値（UserDefaults）
- クラウド利用、Web確認、履歴の本人確認、有料版かどうか
- 今日の日付と利用回数
- 初回ヒントを出し終えたかどうか（入力済み、送信済み）

## 8. プログラム構成
- App.swift：起動
- Models.swift：節と木の定義、道のりの取得、木の一列化、枝の削除
- Engine.swift：AIの差し替え口と指示文
  - SearchRequest：問い、画像、道、避ける候補
  - SearchEngine：name / supportsImages / topics(request) / answer(request)
  - makeEngine()：ふだん使うAIを選ぶ
  - makeDetailEngine()：「もっと詳しく」用のAIを選ぶ（使えなければなし）
  - MockEngine：仮データ
  - OnDeviceEngine：端末内AI（文字のみ、iOS 26以上）
- EngineIOS27.swift：iOS 27の機能（コンパイル条件 IOS27_SDK で有効化）
  - VisionOnDeviceEngine：端末内AI（画像対応）
  - CloudEngine：Private Cloud Compute
- SearchModel.swift：検索の進行、履歴、設定、利用回数、保存
  - start / choose / goBack / regenerate / answerNow / detail /
    reset / resume / delete / deleteAll
- SearchView.swift：検索画面
  （入力、初回ヒント、長押しメニュー、道のり、答え、選択肢、上限の案内、カメラ）
- HistoryView.swift：履歴の木の表示、枝から調べ直し、削除
- SettingsView.swift：設定

## 10. ランニングコスト
- 必ずかかる：Apple Developer Program 年間99米ドル
- 売れたときだけ：App Store手数料
  （Small Business Programなら15%、通常30%）
- かからない：端末内AI、PCC（条件内）、サーバー（持たない）
- 使い方次第：GitHub Actionsのmacランナー（無料枠を超えた分）
- ユーザーが増えても運用費がほぼ増えない構成

## 11. 開発段階
1. 済：検索の流れと履歴の試作（文字入力、仮の見た目）
2. 済：改訂設計の反映（初回ヒント、画像入力、もっと詳しく、Web確認、
   無料版の制限、設定）。ただし一度もコンパイルしていない
3. 進行中：GitHubでビルドを通し、TestFlightで実機確認
4. トピック生成の質の確認：問いを30個ほど用意し、実機で確かめる（最大のリスク）
   - 確認観点：
     ①2〜4タップで収束するか（canAnswerの判定タイミング）
     ②トピックの排他性と粒度の均一性
     ③「別の候補」を押したときの多様性
5. 画像からの検索の実機確認
6. PCCの権限申請と「もっと詳しく」の実機確認
7. 課金（StoreKit）
8. 見た目の設計と仕上げ（動き、触覚、ダークモード、VoiceOver）
9. App Store公開の準備（プライバシーポリシー、審査）

## 13. 類似アプリと差別化
すべての要素を備えたアプリは、2026-11-20の調査では見つからなかった
（App StoreとWebの検索結果に基づく。網羅はしていない）。

- Neural Mindmap：問いから知識の木を作る。iPad向けで情報を広げる方向
- DeeperAI：テーマを木構造で整理する道具。検索ではない。クラウドAI、有料
- Deep Query：要約の後に次の問いを3つ提案。答えを出してから広げる
- AISight：端末内AIで答えを作る。トピック選択も履歴マップもない
- KnowTree：会話の枝分かれを図にする。Webのチャット型

差別化の軸：類似アプリは知識を「広げる」。このアプリは「絞る」。
